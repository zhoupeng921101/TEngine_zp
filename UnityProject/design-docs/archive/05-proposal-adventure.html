提案 P1：Adventure 关卡模式

设计提案 · 待评审 · 在无尽玩法之上加一条「关卡 + 目标 + 星级」的内容线，用现成的 360/2000 关数据撑起长留存。

立项信息
优先级P1 内容量 / 留存
状态待评审
预计工作量首版（冲分关）约 6~9 人日；收集关另计（P2）
依赖建议 P0 打击感 先行（关卡结算需要消除反馈撑场）
关联移植路线图（P1 来源）· 动态难度（复用）

一、背景

  • 当前只有 Classic 无尽一种模式，缺「目标感 / 进度感」，新玩家没有短期目标牵引。
  • 关卡数据已是成品：参考工程带 default360.json（360 关）与 default2000.json（2000 关），结构清晰，含预置棋盘、过关条件、难度区间。
  • 难度系统可复用：关卡数据自带 weightMin/weightMax，能直接驱动现有 dynamicWeight 橡皮筋 做关卡级难度——不必另写一套。
  • 结算资源现成：stars_icons 星级图集 Unity 已有；参考工程的 LevelComplete 结算流程可平移。

二、设计目标

给玩家一条「过关→拿星→解锁下一关」的清晰阶梯。每关一个独特开局（预置障碍）+ 一个明确目标，让「再来一关」的冲动接管。

三、模式架构

Classic（现有）Adventure（新增）
开局棋盘全空关卡 Map[64] 预置障碍/方块
结束条件无解即 GameOver达成目标→通关；无解→失败重试
难度dynamicWeight 自由浮动dynamicWeight 锁定在关卡 weightMin~Max
存档当前局 + 最高分关卡进度 + 每关星级（独立存档）
入口主菜单 Classic 按钮主菜单 Adventure 按钮 → 关卡选择

用一个 mode 字段区分两套流程（参考工程即 state.mode = 'classic' | 'adventure'），核心落子/消除/补块逻辑完全共用。

四、关卡数据结构

每关一条配置，关键字段（源自参考 LevelLoader.LevelConfig）：

字段含义首版是否用
Num关卡编号（1-based）是
Map[64]8×8 初始棋盘：0=空，1-7=预置障碍方块（带色）是
levelTarget / Condition.RequiredScore过关目标分是
Condition.Namescore_to_win 冲分 / collect 收集先做 score
weightMin / weightMax本关 dynamicWeight 锁定区间是
RequiredCollections[]收集要求（Key=9999=分数，其余=元素类型+数量）P2
落地建议： 关卡 JSON 走项目既有的 Luban 表 流程（与权重表同一套管线），转成 .bytes 运行时读取，保持工程一致性。360 关先行，2000 关作为内容储备。

五、过关条件（首版：冲分 score_to_win）

360 关中 246 关是冲分关，覆盖率最高，首版只做这一种即可形成完整闭环：

  • 落子/消除后实时检测：当前分 ≥ levelTarget → 触发通关。
  • 若手牌无解且未达标 → 关卡失败，可重试本关。
  • 防重复触发（参考工程用 levelCompletedTriggered 标志位）。

六、星级系统

按「最终得分 / 目标分」的比值评 1~3 星，比值阈值来自 stars.ratios = [1.0, 1.5, 2.0]：

条件星级
得分 ≥ 目标 × 1.0★☆☆ 1 星（过关）
得分 ≥ 目标 × 1.5★★☆ 2 星
得分 ≥ 目标 × 2.0★★★ 3 星
星级给了「重刷高分」的二次目标——1 星过关的玩家会为 3 星回来。这是关卡模式留存的关键钩子。ratios 建议可配，方便整体调松紧。

七、难度：复用 DDA + 关卡锁区间（设计亮点）

不新建难度系统。关卡载入时把 dynamicWeight 的活动范围钳制在本关 weightMin~weightMax：

  • 想让某关「轻松爽快」→ 区间设在负值段（橡皮筋只在放水档活动，多发 Fill/清盘块）。
  • 想让某关「步步惊心」→ 区间设在正值段（锁在做局档，多发困难块）。
  • 想让某关「正常波动」→ 给一个跨 0 的宽区间。

等于把一套连续可调的难度旋钮，按关编排成难度曲线。同一套算法，零额外开发，纯靠配表产出 360 关的难度节奏。

八、关卡流程

  1. 主菜单点 Adventure → 进入关卡选择（显示已解锁关卡 + 已得星数）。
  2. 选关 → 载入 Map 铺预置棋盘、锁 weightMin/Max、读 levelTarget，顶部显示 TARGET。
  3. 正常玩（落子/消除/补块，共用 Classic 核心）。
  4. 达标 → 延迟约 700ms → 弹 LevelComplete 结算窗（LEVEL N COMPLETE + 星级逐颗弹出 + 得分/目标）。
  5. 结算窗操作：下一关 / 重玩 / 返回关卡选择；写入关卡进度与星级存档。

十二、验收标准

  • 主菜单可进入 Adventure；关卡选择能看到解锁关卡与星数。
  • 进关正确铺预置棋盘、显示目标分、难度锁在关卡区间。
  • 达标即通关，按 1.0/1.5/2.0 正确评星，弹出结算窗。
  • 可进下一关 / 重玩；进度与星级正确存档、重启后保留。
  • Classic 模式不受影响（回归测试）。

十三、风险

风险应对
关卡 JSON 字段含义未完全吃透（modeType/levelType 等）首版只用确定字段（Map/target/weight/condition），其余忽略
预置障碍与 DDA 算法的「可放性」交互未验证M2 重点测：带障碍开局时 RandomNoDie 兜底是否仍保证有解
关卡难度曲线需大量调试先批量导入跑通，再按数据/体感逐段调 weight 区间
收集模式工程量大明确切到 P2，不阻塞冲分关上线
