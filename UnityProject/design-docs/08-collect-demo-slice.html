独立收集 Demo 切片（方案 A）

不依赖完整关卡框架的最小可跑垂直切片：在现有 Classic 无尽玩法之上，加「元素生成 + 收集计数 + collect 达标判定 + 简单 UI」，做成单关 demo。一条能跑通的最短路径，验证收集玩法机制，为日后 Adventure 关卡模式 的 collect 关打底。

立项信息
类型垂直切片 / Demo 机制验证，非正式关卡内容

一、为什么先做独立切片

  • 收集玩法是原版的两大过关条件之一（路线图统计：360 关里 114 关是 collect）。要还原它，机制必须先跑通。
  • 完整关卡框架太重：LevelLoader、Map[64] 障碍解析、关卡选择、星级存档、360/2000 关数据导入……一次性全做风险高、周期长。
  • 切片策略：把收集机制从关卡框架里剥出来，挂在已经跑通的 Classic 无尽玩法上，做成「空棋盘 + 一个收集目标」的单关 demo。先验证元素怎么生成、怎么计数、怎么判定达标这三件核心事，UI 够用即可。
  • 收益：机制一旦验证，搬进 Adventure 的 collect 关只是「换数据来源（静态 demo 配置 → 关卡 JSON 的 RequiredCollections[]）+ 接关卡流程」。

二、原版机制还原（参考工程 template-vite-ts-zp）

逆向自参考工程（Phaser4 + TS）。关键文件与机制如下，Unity 切片按此复刻。

2.1 元素类型与 Key 映射

源 src/game/core/GameState.ts。原版有 9 种收集元素，每种对应原游戏配置里的一个 Key：

KeyElementType原版 glyph说明
100diamond ◆◆原版用纯文字符号渲染，零美术依赖。Unity 切片可直接沿用 glyph / 纯色块，无需新图集。
101pentagon ⬟⬟
102star ★★
103heart ♥♥
104sun ☀☀
105moon ☾☾
106leaf ✿✿
107crown ♕♕
200stone ⬢⬢
RequiredCollections[] 结构（源 LevelLoader.ts 的 RequiredCollection { Key, Value }）：一关的收集要求是一组 {Key, Value}。
  • Key == 9999 → 表示分数目标（与收集并存的冲分条件），收集解析时跳过。
  • Key ∈ {100–107, 200} → 表示元素类型 + 数量（Value = 要收集的个数）。
解析时 COLLECT_KEY_MAP[Key] → ElementType，把同类型 Value 累加成 collectionTargets[type]。

2.2 元素叠加层（与棋盘平行）

原版用一张与 saveArr 平行的 elementArr[8][8]（ElementType | null）记录「哪个格子上贴了哪个收集元素」。元素是方块格的附着物——格子被填，元素就在格上；格子被消除，元素就被收集。两个计数器：collectionTargets{}（目标）与 collected{}（已收集）。

2.3 元素从哪来（两条来源）

来源原版做法（文件 / 函数）切片是否采用
A. 障碍格预置 Game.ts → seedCollectionElements()：关卡开局把 Map[64] 的预置障碍格洗牌，按每类型 min(剩余, max(2, floor(target×0.6))) 个，在障碍格上播种元素。 可选 切片默认空棋盘、无 Map 障碍，故此来源默认不用；如需「一进场就有收集物」可选做少量初始预置（见 §3.3）。
B. 候选块携带 GameState.ts → buildPiece()：收集模式下，对候选方块的每个填充格按 ~22% 概率注入一个「仍需收集」的元素类型（已达标的类型不再生成）。落子时元素随方块格转移到棋盘。 主来源 切片靠这条持续产出收集物，不依赖关卡 Map。

2.4 落子转移 → 消除计数 → 达标判定（核心链路）

阶段原版逻辑（文件）
落子转移GameState.placePiece()：按形状填充格顺序（行优先 cellIdx），把 piece.elements[cellIdx] 写入 elementArr[posRow+r][posCol+c]。元素位置与方块格一一对应。
消除计数Game.ts（消除流程）：消行/列时遍历被清格，若 elementArr[r][c] 有元素 → collected[elem]++，并清空该格 overlay；随后 refreshCollectCounters() 刷新顶部 UI + 元素飞向计数器动画。
达标判定GameState.isCollectionComplete()：所有类型 collected[t] ≥ collectionTargets[t] 即达标。checkLevelComplete() 在收集模式下：达标 → 评星（calcCollectionStars() 按步数效率）→ 进结算。
原版星级（步数效率）：moves ≤ ceil(total×0.6) → 3 星；≤ total → 2 星；否则 1 星（total = 所有目标数量之和）。切片简化：达标即胜，星级评定砍掉（属关卡结算范畴，见 §4 不做项）。

三、Unity 切片范围

3.1 做什么（In Scope）

  • 元素数据模型：9 种元素枚举 + Key 映射（100–107 / 200 / 9999）+ 一份静态 demo 收集目标（如 ◆×10、★×8，硬编码，不接表）。
  • 元素叠加层：与 SaveArr 平行的 ElementArr[8][8] + Collected / CollectionTargets 两个计数字典。
  • 元素生成：候选块携带（复刻 buildPiece 的 ~22% 注入，只出「仍需收集」类型）。
  • 落子转移：落子时把方块携带的元素写入棋盘 overlay。
  • 收集计数：消行/列时统计被清格元素，累加 Collected，清 overlay。
  • 达标判定：所有目标 Collected ≥ Target → 触发胜利。
  • 简单 UI：顶部收集计数条（图标 + got/target，达标变绿）；胜利面板（达成提示 + 返回 / 重开）；棋盘格上元素图标渲染。
  • Demo 入口与重置：从主菜单进入收集 demo；进入即重置（空棋盘 + 清计数 + 补块）。

3.2 不做什么（Out of Scope —— 严格锁定切片边界）

砍掉的东西为什么不在切片里
LevelLoader / 360 / 2000 关 JSON 导入切片用静态 demo 目标，不接关卡数据来源
Map[64] 障碍棋盘解析、障碍格预置元素切片空棋盘起手，元素只靠候选块携带
关卡选择 / 多关进度 / 解锁链这是「单关 demo」，不是关卡系统
星级评定（步数效率 / 分数 ratios）属关卡结算，切片只做「达标即胜」
score_to_win 冲分条件（Key 9999）切片只验证收集，分数目标解析时跳过
collect 进度存档Demo 每次进入从零开始，不持久化收集进度
变现 / 体力 / 道具 / 广告复活项目方向：离线还原、去变现

四、核心系统设计

4.1 数据模型

结构设计对应原版
CollectElement（枚举）Diamond=100…Crown=107, Stone=200。建议直接用 Key 值作枚举值，省一层映射。ElementType + COLLECT_KEY_MAP
Demo 目标配置静态：(◆,10),(★,8) 之类。一处常量，方便改数验证。RequiredCollections[]（去掉 Key 9999）
元素叠加层ElementArr[8][8]，0/None 表示无元素。elementArr
计数器CollectionTargets<CollectElement,int>、Collected<CollectElement,int>。collectionTargets / collected
CollectMode 开关布尔门控。off 时叠加层 / 生成逻辑全部短路，Classic 行为零变化。原版 isCollectionMode()

4.2 元素生成（候选块携带）

复刻 buildPiece：收集模式下，对候选方块每个填充格按 ~22% 概率注入一个「仍需收集」类型（Collected[t] < Target[t] 的类型集合里随机抽）；若该类型已达标则从候选池剔除，避免「凑齐了还在出」。概率与「仍需类型集合」均建议设为可调常量，方便配平节奏。

4.3 落子转移 → 消除计数 → 达标

核心链路（与原版同构）：
候选块携带元素 → 落子 按填充格顺序写入 ElementArr → 消行/列 时遍历被清格，有元素则 Collected[t]++ 并清 overlay → 刷新顶部计数 → 所有 Collected ≥ Target → 弹胜利面板。

4.4 UI

UI 元素设计
顶部收集计数条每个活跃类型一格：图标 + got/target。实时刷新；某项达标 → 文字变绿。
棋盘元素渲染在方块格上叠一层元素图标（glyph / 纯色点）；落子显示、被消时移除（可选飞向计数器的动画）。
胜利面板「收集完成！」+ 各目标达成列表 + 「返回主菜单 / 再来一局」按钮。弹出后锁输入。
（复用）GameOver无可落子且未达标，复用现有 GameOver 面板。

五、与现有 BlockBlast 模块的挂接点

切片建议加法式挂接：新增字段 / 方法 + 新建窗口，已有 Classic 逻辑在 CollectMode=off 时完全不变。

七、风险

风险应对
纯靠候选块携带，凑齐最后 1~2 个元素可能很慢（看脸）注入概率 / 仅出仍需类型设为可调；必要时开 §3.3 的初始预置（B 来源）兜底出镜
元素已达标后仍出该类型，浪费手感buildPiece 注入只从「Collected < Target」集合抽（已复刻原版逻辑）
collect 分支污染 Classic 落子 / 消除 / 存档全部 collect 逻辑 CollectMode 门控 + 独立窗口；Classic 回归测试为硬验收
元素与方块格的填充顺序错位（图标贴错格）转移用与 PlacePiece 完全相同的行优先 + 位判断遍历，落子后目视核对位置
无解但未达标时的体验（卡死）切片复用现有 GameOver；demo 目标数值调小，降低卡死概率
