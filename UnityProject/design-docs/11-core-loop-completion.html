核心玩法补全

把四份原始策划稿(方块玩法 / 订单 / 宝箱 / 女神)里的漏洞与空缺补成完整、自洽、可验收的一套设计。八个挂账问题逐条给确定答案——并发模型、连消/多消/全清结算、体力系统、货币与术语统一、图案经济数值、智能生成算法仲裁、宝箱、女神。术语与工程现状(09/10 的 merge-order 语义)对齐,不另起第二套概念。

本篇是融合玩法的完整设计:游戏为单入口循环——经典无尽融合进合成订单,无「纯无尽」独立入口,保留体力预算。本篇补全的这套系统(并发订单 / 连消多消全清 / 体力 / 经济 / 智能生成 / 宝箱 / 女神)即融合玩法的上层设计,经典 DDA / 计分 / 连消钩子是其底层。顶层裁决、经典各机制的保留/被覆盖清单、三处跨模式状态隐患见 29·§三 与 29·§五。
读前必看 · 本篇与工程现状的关系(单一事实源)

当前已落地的是一条刻意收窄的垂直切片(merge-order demo):合成封顶 Lv3、双订单、硬编码配置、消除得分驱动元素、无宝箱/女神。原始策划稿描述的是一套完整商业体量的游戏(图案 5 级、四类订单、宝箱、女神、双货币、11 挂件)。两者不是替代关系,而是同一款游戏的两个完成度:

  • 代码 = 当前真相。本篇凡涉及已落地系统(合成/订单/体力/元素生成),数值与符号对齐 MergeOrderConfig / MergeElement 现状,在其上扩展,绝不另立一套常量。
  • 本篇 = 完整目标。补全的系统(宝箱/女神/完整订单四类/图案多级经济)按完整游戏设计,但每节标注「现状 / 本篇新增」,让 dev 一眼看清哪些是已有、哪些是要建。
  • 分期落地不在本篇决策范围。本篇只产出「完整且自洽的设计 + 验收标准」,具体哪批先做由 boss 排期。设计自带「可降级到 demo 范围」的开关说明,便于切片。

二、完整核心循环(把八个系统串起来)

原稿四份文档各讲一块,缺一张「谁喂谁」的全局图。补一张:方块层是唯一产出引擎,所有下游系统(合成/订单/宝箱/女神)都靠它驱动;订单是主经济枢纽,宝箱/女神是叠加的进度奖励层。

  • 唯一产出动作是落子:体力、图案、连消/多消/全清、女神进度,全部由「落子→消除」这一个动作派生。订单是把图案变现为资源(灵力 + 宝箱)的出口,资源再回灌体力,闭环。
  • 叠加奖励层(黄)不参与核心循环的资源平衡:连消/多消/全清、宝箱、女神都是额外给予,拿不到也能正常玩。它们提供节奏惊喜与长线目标,但核心可玩性只依赖「落子→消除→订单」主链。这条原则保证后续按需切片时可以先砍奖励层、保住主链。

三、订单并发模型 问题 1

矛盾:方块稿写「同时最多 1 个订单」,订单稿定义了四类(常规/加急/剧情/黄金时段)可并行。直接并存四类会让界面挤、决策乱;只留 1 单又浪费「双货币四类」的设计。

定:双轨并发模型(常驻日常轨 + 可选特殊轨)。同屏订单槽固定布局,封顶 3 单:
轨槽数承载订单类型刷新方式
日常轨(常驻)2(= 现状 ActiveOrders=2)常规订单交付即刷新下一单(锯齿波节奏,见 §六)
特殊轨(可选)0 或 1加急 / 剧情 / 黄金时段三类分时复用同一槽(同时只占一个)按各自触发条件出现;加急带倒计时,过期消失;剧情手动接取;黄金时段按游戏内钟点出现

为何特殊轨三类共用一槽、且只 1 个:三类都是「高价值、低频、要玩家特别关注」的订单——同屏只放一个,玩家心智不分裂,且天然规避「加急和剧情同时倒计时」的焦虑叠加。三类的优先级(同一时刻多个想占槽时听谁的):

特殊槽占用优先级（高 → 低）：
  剧情/主线单   ＞  加急单（倒计时）  ＞  黄金时段单
  · 剧情单是进度唯一钥匙，最高：一旦满足触发条件就占槽，不被抢
  · 剧情槽空 时，加急单可占（加急是限时高收益，比黄金时段更稀缺）
  · 二者都不在时，黄金时段单在游戏内 12–14 / 18–20 点占槽
  · 已占槽的订单不被更高优先级中途踢出（避免玩家正在凑的单凭空消失）；
    新的高优先级单进等待队列，待当前特殊单交付/过期后再上
降级到 demo 范围:当前切片只有日常轨(ActiveOrders=2),特殊轨 = 0 槽即为现状。本节的特殊轨是本篇新增,落地时新增 1 个特殊槽 + 三类订单的触发器,日常轨零改动。剧情单的「死锁防护」见 §六·剧情订单(终极神物必须可在合理时间内凑出)。

四、货币与术语统一 问题 4

原稿混用两套词汇:方块稿用「图案/收集区/合成」,订单稿残留 merge 游戏术语「食材/生成器/仓库」,还引入「虔诚币/灵力/终极神物」三个未定义名词。统一为一套,且与工程现状(MergeElement/收集区/合成)对齐。

4.1 货币:双货币降为单货币(灵力)

判定:砍掉「虔诚币」,只保留「灵力」一种软货币。原稿设双货币(虔诚币 = 订单主奖励,灵力 = 少量副产),但去变现后双货币失去存在理由:
  • 双货币的常见目的是「软货币管养成、硬货币(付费)管加速」,或「主货币买大件、副货币买消耗」。本作无付费、无商店(项目红线),两种软货币会各自找不到独立花销出口,沦为两条并行的数字,徒增理解成本。
  • 合并为单货币「灵力」:既是订单/宝箱/女神的统一奖励,又是养成(神庙进度推进)的统一消耗。一种货币、一个钱包、一条收支线,清晰可平衡。
  • 原「虔诚币」的语义(向神庙的供奉)并入灵力的用途——灵力既驱动局内(体力关系见 §七),又作为神庙养成的供奉资源。
单货币方案已于 2026-06-12 拍板(§十二 #2);若后续重开付费或需叙事区分而恢复双货币,须另设两者独立用途并重算奖励口径。

五、连消 / 多消 / 全清:结算规则 问题 2

混用根源:原稿「多消奖励档位」用的是连击术语(3 连击 = Great = 1 中级…),但又说「多消按单次同时消除行列数」——到底按「连续放置连击数」还是「单次同时消除行列数」?二者是两个正交维度,必须拆开,各给一张表,再定叠加时的结算顺序。

5.1 两个正交维度的定义

维度定义计量清零条件
多消(Multi-clear)单次落子同时清掉的行+列总数该次落子清除的行列条数(1=单消,2=双消,3=三消,4=四消…)每次落子独立结算,不跨手累积
连消(Combo)连续多次落子每次都有消除,形成的不中断链连续触发消除的落子次数(链长 1→2→3…)某次落子未触发任何消除 → 链断、计数归 1
全清(All-clear)一次消除后整个 8×8 棋盘清空布尔事件(发生 / 不发生)—(独立事件)
术语裁决:原稿「3 连击 = Great」的「连击」实指多消(单次同时消行列数),因为它后面紧跟「3 连击 = 1 中级图案」这种单次结算的奖励——连续落子链的奖励原稿没设计。本篇明确:即时弹字(Good/Amazing/...)绑多消;额外图案奖励也绑多消;连消另给一条独立的递增分数加成(新增,填补原稿空缺);全清独立发大奖。

对齐现状:元素产出已由得分驱动(消得越狠图案越多,ElementsForScore 已封顶 4)。本表的「额外图案奖励」是在得分驱动产出之上的多消里程碑加码——把原稿「3 连击=1 中级」的设计接进来,作为高多消的升级奖(直接给中/高级,跳过合成)。

事件奖励约束

5.5 三者叠加时的结算顺序(关键)

一次落子可能同时触发多消、连消、全清(例:连续第 3 手、本手四消、且清空棋盘)。结算必须有确定顺序,否则倍率施加对象有歧义、可单测性丧失。

单次落子的结算流水线（顺序固定）：

1. 落子 → 扣体力 PlaceCost                          // §七
2. 判定消除 → 得 clearedCells, lines（多消数）
   若 lines == 0：
     · 连消链清零（combo = 1）
     · 全清武装位重置（见步 6）
     · 结束（无消除分支）
3. 基础消除得分 baseScore = ClearScore(clearedCells, lines)   // 复用 BlockScoring
4. 连消加成：combo += 1; displayScore = baseScore × ComboMult(combo)   // §5.3，仅作用显示分
5. 元素产出：k = ElementsForScore(baseScore)  // §六，用【未乘连消】的 baseScore，避免连消刷图案
   · 基础产出 k 个 Lv1 入队（得分驱动，现状逻辑）
   · 多消里程碑加码：按 §5.2 表，lines≥3 时额外发 Lv2/Lv3 直接入收集区
6. 全清判定：若棋盘清空 且 全清武装位 == true：
     · 发 Lv3 + 换背景 + 女神 +1（§5.4 / §十）
     · 全清武装位 = false（本次已发，连续第二次不再发）
   否则（未清空）：全清武装位 = true（重新武装）
7. 体力返还：ClearRefund += lines                  // §七
8. 刷新 UI：弹字（多消档 §5.2）、分数、收集区、订单可交付检查

> 顺序铁律：连消倍率只乘【显示分】，绝不参与【元素产出】与【全清判定】。
> 这条隔离保证「会连消的玩家拿高分爽感」与「图案经济不被连消通胀」两件事互不污染——
> 二者一旦耦合，连消就会变成刷图案的捷径，§六的经济平衡全盘失效。

六、图案经济:数值框架 问题 5

本节的图案经济是合成订单的完整循环,也是融合玩法唯一的经济——单入口循环下不存在「与纯无尽刷分并列的另一套经济」需要平衡。融合裁决(经济/计分口径维持现状、不另立常量)见 29·§三 与 29·§4.1。

6.1 先决判定:5 级深度不合理,降为 3 级

原稿 5 级 + 4 进 1 = 顶级图案需 256 个初级。这个深度对本作不合理,建议降为 3 级(对齐现状 MaxLevel=3)。理由(具体到机制后果):
  1. 自动配对让高级图案的边际产速指数衰减:现状自动配对(满 2 即合,见 09·§3.1)下,每个非封顶等级库存恒 ≤1。要出 1 个 Lv5 需 16 个 Lv1 一路喂上来;按 §6.3 的产速(熟练约 1.5 图案/落子),凑一个 Lv5 要约 11 次落子且全程不挪用——而订单还在持续消耗低级图案,Lv5 实际几乎永远凑不齐,顶级订单死锁。
  2. 5 级的「特/顶」两级在 demo 体量下无内容承载:原稿让 Lv4/Lv5 对应剧情终极神物,但剧情系统(神庙进度)尚未建。多出的两级是悬空深度——没有订单/玩法实际消费它们,纯属数字膨胀。
  3. 3 级已满足全部订单形态:常规单要 Lv1/Lv2,加急/剧情要 Lv3 组合(见 §6.4)。3 级的折算深度(Lv3 = 4 个 Lv1)正好卡在「要攒、但 5–10 分钟够得着」的甜区。
决定:封顶 Lv3(= 现状)。原 5 级的「初/中/高/特/顶」收敛为 Lv1(初)/Lv2(中)/Lv3(高);「特/顶」语义并入「高级 + 剧情组合需求」(用多个 Lv3 + 多类型组合表达高难度,而非更高单级)。封顶 Lv3 已于 2026-06-12 拍板(§十二 #1);若未来恢复 5 级深度,需先建神庙剧情系统承接 Lv4/Lv5,并重设自动配对(可能改手动合成)。

6.2 地基约束:自动配对 ⇒ 订单可满足形态受限

这是整套经济的地基,工程现状已在 MergeOrderConfig.OrderPool 注释里钉死,本篇遵从并解释清楚:

自动配对使每个 (类型, 非封顶等级) 的库存恒 ≤ 1(满 2 立即升级)。直接后果:

  • Lv1 / Lv2 订单的数量只能为 1:收集区里同时绝不会有 2 个 Lv1-◆(第 2 个一到就合成 Lv2)。所以「◆ Lv1 ×3」这种订单结构上不可满足——原稿的「需求 1–3 个图案」对低级图案不成立。
  • 只有封顶 Lv3 可堆积,数量方可 ≥ 2:Lv3 不再向上合并,可在收集区累积多个。所以「数量 ≥ 2 的订单」必须是 Lv3。

合法订单形态(收敛后):

等级合法数量示例
Lv1恒 1◆ Lv1 ×1
Lv2恒 1★ Lv2 ×1
Lv31 ~ N(可堆积)★ Lv3 ×2、◆ Lv3 ×3
多类型组合各类型按上行规则◆ Lv2 ×1 + ★ Lv3 ×2(用于加急/剧情)

用「多类型组合 + Lv3 堆积」表达高难度,而非靠单类型大数量——这既绕开自动配对约束,又让高级订单需要玩家同时经营多条图案线,难度自然上来。

7.1 灵力与体力的关系(原稿未定,本篇补)

定:灵力与体力分离,但灵力可兑体力(限量、非购买)。
  • 体力 = 局内落子预算(短周期、单局尺度)。灵力 = 跨局软货币(长周期、养成尺度)。二者不合并——合并会让「攒养成货币」和「当下能不能落子」互相挤压。
  • 兑换口子(去变现兜底):体力耗尽且想继续时,可花灵力祈愿补体力(如 20 灵力换 10 体力),每日限 N 次(默认 3),纯灵力消耗、无任何付费/广告。这是去变现版的「续命」——用玩家自己攒的软货币,不引入外部变现。超次数则只能等自然恢复或结束本局。

7.2 消除锤 20 体力的合理性(原稿未论证,本篇补)

原稿:消除锤道具花 20 体力摧毁待选区一个方块(用于清掉挡手的烂方块)。20 体力 = 起始体力的全部、软上限的 2/3、约 20 次落子的预算——这个代价合理吗?

判定:20 偏高,建议降为 8(= 一个订单奖励的体力),作为「应急但肉疼」的定位。理由:
  • 20 体力几乎是整局预算,玩家几乎永远不会用——道具形同虚设,设计无意义。
  • 消除锤解决的是「待选区发了三个烂方块,落哪个都恶心」的真实痛点,与「智能生成防卡死规则」(§八)互补:防卡死兜「无处可落」,消除锤兜「能落但都不想落」。它该是偶尔可用的解围,不是奢侈品。
  • 定 8 体力 = 一单的回血,意味着「用一次锤 = 白做一单」,代价真实存在(肉疼),但不至于用不起。可调常量 HammerCost,test 配平。
HammerCost=8 已于 2026-06-12 拍板(§十二 #3);若实测出现滥用,可上调至 12~20(单常量,改动无连带)。

7.3 体力耗尽的局内行为(原稿未定,本篇补)

体力 < PlaceCost 且仍有手持候选块（无法落子）时：
  1. 不立即 GameOver，先给玩家三条出路（按可用性排列）：
     a. 等自然恢复（若实装）—— 显示「下次回复倒计时」
     b. 花灵力祈愿补体力（§7.1，每日限次）
     c. 用本局剩余宝箱/女神奖励里若含体力，提示去领
  2. 三条路都走不通（无灵力、无恢复、无奖励）→ 软 GameOver「精力耗尽」面板
     （复用现状 GameOverWindow 变体标题，见 09·§七）
  3. 软 GameOver 不清空已攒图案与灵力（跨局保留）；下次进来体力已部分恢复，可续。

八、智能生成算法:优先级仲裁 + 补完 问题 6

原方块稿给了 4 条发牌规则但标注「未完待续」,且没说互斥时听谁的。本节定优先级链并补完伪代码。4 条规则:

规则原稿意图触发条件
R1 清盘后连发异形清盘(全清)后连发 3 个异形块增难,防止全清太爽刚发生全清,且 anti-streak 计数 < 3
R2 连续未消除发可消方块连续 5 次落子没消除 → 发一个能立即消除的方块,防卡死/防挫败noClearStreak ≥ 5
R3 高阶消除引导检测到玩家能凑多消时,发引导其打出高多消的方块棋盘存在「再放某形状即可三消+」的局面
R4 清盘引导棋盘接近清空时,发能促成全清的方块剩余非空格 ≤ 阈值且存在可全清的发牌
互斥仲裁:严格优先级链(防挫败 > 控难度 > 给惊喜)。同一手多条规则都想生效时,高优先级独占该手发牌,低优先级让位: 
优先级（高 → 低）：

  P0  R2 防卡死        —— 玩家正在受苦（连续不消除/濒临死局），最高，无条件优先
  P1  R1 清盘后增难    —— 节奏控制，紧随其后（防止全清后立刻又全清的失控正反馈）
  P2  R4 清盘引导      —— 给惊喜，但仅在不与 P0/P1 冲突时
  P3  R3 高阶引导      —— 锦上添花，最低
  P4  常规动态难度发牌  —— 都不触发时，走现有 dynamicWeight 橡皮筋（见 02 文档）

裁决铁律：
  · P0 与 P1 永不同时（R2 要求「能消」，R1 要求「异形难消」——直接矛盾）。
    P0 优先：玩家在受苦时，防卡死压倒增难。R1 的 anti-streak 计数此手暂停递减。
  · P2 与 P3 可降级合并：若某发牌同时满足「促全清」与「促高多消」，按 P2 处理。
  · 任一手最终只采纳一条规则的发牌建议；其余规则的内部计数照常更新（不因让位而清零）。

8.1 补完的完整伪代码(「未完待续」收尾)

// 每次需要补发候选块时调用（手牌耗尽 → 补一组 3 块）
GenerateNextHand(board, ctx):
    hand = []
    for slot in 0..2:
        block = SelectBlockForSlot(board, ctx, slot)
        hand.append(block)
        board.SimulatePlacePreview(block, ctx)   // 让同组后续块感知前块影响（防一组全卡）
    ctx.AdvanceCounters()                          // 更新 noClearStreak / antiStreak 等
    return hand

SelectBlockForSlot(board, ctx, slot):
    // —— P0 防卡死（最高）——
    if ctx.noClearStreak >= NO_CLEAR_THRESHOLD (=5):
        b = PickBlockThatEnablesImmediateClear(board)   // 找一个放下即可消的形状
        if b != null:
            ctx.markRescue()                            // 本组已救，避免整组都塞简单块
            return b
        // 找不到可消形状（棋盘太满）→ 退而求其次：发最小占格形状
        return PickSmallestFootprintBlock()

    // —— P1 清盘后增难 ——
    if ctx.antiStreak > 0:                               // 全清后剩余的「连发异形」配额
        ctx.antiStreak -= 1
        return PickAwkwardBlock(board)                   // L/Z/T 等异形，增加摆放难度

    // —— P2 清盘引导 ——
    if board.NonEmptyCells() <= CLEAR_GUIDE_THRESHOLD:
        b = PickBlockThatEnablesAllClear(board)
        if b != null: return b

    // —— P3 高阶消除引导 ——
    if board.HasMultiClearOpportunity(minLines=3):
        b = PickBlockThatEnablesMultiClear(board, minLines=3)
        if b != null: return b

    // —— P4 常规：现有动态难度橡皮筋 ——
    return DynamicWeightPick(board, ctx)                 // 见 02 文档 dynamicWeight

// 计数器更新（每次落子后）
OnPlaced(clearedLines):
    if clearedLines == 0: ctx.noClearStreak += 1
    else:                 ctx.noClearStreak = 0
    if isAllClear(): ctx.antiStreak = ANTI_STREAK_COUNT (=3)   // 全清后武装 3 个异形配额

可调常量：NO_CLEAR_THRESHOLD=5 · ANTI_STREAK_COUNT=3 · CLEAR_GUIDE_THRESHOLD=8（剩余非空格）
        · 高阶引导 minLines=3
与现状的关系:R4(常规动态难度)= 工程已实现的 dynamicWeight 橡皮筋(见 02 文档)。R1–R3 + 优先级链是本篇新增的上层仲裁,套在现有发牌之外:四条特殊规则都不触发时,完全回落到现状发牌,现状行为零改变。这保证智能生成可作为独立增强分批落地。

满档奖励好评条满 10 → 触发「好评如潮」弹窗 → 发档位奖励 → 好评条清零、进入下一档(周期循环)
奖励档位(升序)女神有多个「好感等级」,每满 10 次全清升 1 级,奖励逐级加码:Lv1 满 → 灵力 + 1 史诗宝箱;Lv2 满 → 更多灵力 + Lv3 图案;…越往后越丰厚。给长线玩家「养女神」的目标感
周期重置好评条每档循环重置(满 10 清零再攒);女神好感等级只升不降(永久累积,体现长线投入)。可选「赛季制」让好感等级周期性软重置(列后续,本篇默认只升不降)
换背景女神好感升级时解锁新背景(对齐原稿「全清换背景」)——把全清的视觉奖励(换背景)与女神进度统一,不再是两套独立的换背景
与全清奖励的关系(去重):§5.4 的「全清即时奖」(1 Lv3 + 换背景)是每次全清的即时给予;女神是全清的累计进度(攒 10 次的里程碑大奖)。二者不重复:即时奖管「这一次爽」,女神管「攒够了的长线爽」。换背景统一归女神升级触发,§5.4 的「换背景」改为「推进女神 +1」(女神升级时才换),避免每次全清都换背景的频繁打扰。
降级到 demo 范围:女神是本篇新增系统。最小版 = 单档好评条(全清 +1,满 10 发一次奖),好感多级 + 赛季列后续。现状切片无女神,落地时新增计数器 + 满档弹窗(可复用 MergeOrderWinWindow 风格)。

十一、验收标准(给 test 逐条核对)

验收性质说明:本篇为完整游戏设计,含大量「本篇新增、未落地」系统。验收分两类:(A) 与现状对齐项——可立即对照代码核验;(B) 新增系统设计项——dev 落地后按此核验。test 按系统是否已落地选择适用类。

问题 1 · 并发模型

  • 日常轨固定 2 槽(对齐 ActiveOrders=2);特殊轨 0 或 1 槽,封顶同屏 3 单。
  • 特殊槽占用优先级:剧情 > 加急 > 黄金时段;已占槽订单不被中途踢出,高优先级单进等待队列。

问题 2 · 连消/多消/全清

  • 多消按单次落子清行列数结算(1~6+),弹字与里程碑加码逐档对齐 §5.2 表(3 消 +1 Lv2、4 消 +1 Lv2+1 Lv1、5 消 +1 Lv2+2 Lv1、6+ 消 +1 Lv3)。
  • 连消按连续消除落子链结算,倍率 ×1.0/1.2/1.5/1.8/2.0 封顶,链断回 ×1.0;倍率仅作用显示分,不影响 ElementsForScore 元素产出(关键隔离,可单测)。
  • 全清发 1 Lv3,且不可连续触发 2 次(武装位机制,§5.5)。
  • 结算顺序按 §5.5 流水线:连消倍率不参与元素产出与全清判定。

问题 3 · 体力

  • 体力档对齐 MergeOrderConfig(起始 20/上限 30/落子 -1/消除返/订单 +8)。
  • 灵力可祈愿兑体力,每日限次,纯灵力消耗无付费(§7.1)。
  • 消除锤代价 = HammerCost(建议 8,可调);耗尽走「三出路 → 软 GameOver」流程,跨局保留图案/灵力(§7.3)。

问题 4 · 术语/货币

  • 统一术语:图案/收集区/合成/灵力/体力(§4.2 表);无「食材/生成器/仓库/虔诚币」残留。
  • 单货币(灵力),订单/宝箱/女神奖励 + 养成消耗统一走灵力。

问题 5 · 图案经济

  • 封顶 Lv3(对齐 MaxLevel=3);订单需求遵自动配对约束:Lv1/Lv2 数量恒 1,仅 Lv3 可堆积 ≥2(§6.2)。
  • 常规单 3~12 落子可完成;剧情单总折算 ≤ 36 Lv1、需求等级 ≤ Lv3(不死锁,§6.4)。
  • 完成 5 单(DemoGoalOrders)体力净正,不饿死(§6.5)。

问题 6 · 智能生成

  • 4 规则优先级链:防卡死 > 清盘增难 > 清盘引导 > 高阶引导 > 常规;任一手只采纳一条规则发牌,其余计数照常更新。
  • R2 与 R1 互斥时 R2 优先(防卡死压倒增难);四规则都不触发时回落现状 dynamicWeight,现状行为零改变。
  • 计数器更新按 §8.1 伪代码(noClearStreak/antiStreak)。

问题 7 · 宝箱

  • 生命周期:获取 → 占箱位(4 位)→ 倒计时 → 开箱三选一 → 领取腾位;箱位满时新宝箱不入位。
  • 倒计时不可付费/广告跳过(去变现);三选一从箱级奖池抽 3 不重复项。
  • 来源与常规订单解耦(消除掉落 / 加急单 / 女神满级 / 活动)。

问题 8 · 女神

  • 好评条 = 全清累计计数,显示 N/10,每全清 +1,满 10 发奖 + 清零循环。
  • 女神好感多档升序加码,好感等级只升不降;升级解锁新背景(换背景统一归女神,§十)。
