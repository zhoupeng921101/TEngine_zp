元素合成 + 订单 + 体力 Demo 切片

在 收集 Demo 切片（候选块携带元素 → 消除掉落）之上，叠加三套系统组成一条可自持的核心循环：体力 → 落子 → 消除 → 元素 → 合成 → 订单交付 → 奖励。消除产出的元素不再只是累加进静态计数，而是落入合成区两两合并升级；订单反向拉动玩家去消除指定元素，交付得奖励并刷新下一单。一条技巧驱动的正反馈链。

立项信息
类型垂直切片 / Demo 核心循环验证，非正式关卡内容
基线收集 Demo 切片（已落地） + 其实现（BlockGameState 元素层 / CollectDemoWindow）
方向约束离线还原 · 去变现（体力无购买 / 无广告复活 / 无道具内购——项目红线）
竞品参照浪漫餐厅 / Gossip Harbor 的订单冷却刷新 + 锯齿波难度 + 体力模型（取材不照抄，数值按本作局长重算，见 §六）
范围优先级订单闭环优先（订单 → 交付 → 奖励 → 刷新跑通）；锯齿波难度可做简化实现，完整规则进文档

一、这一切片在 08 之上加什么

08 收集切片已经跑通了一条链路：候选块携带元素 → 落子转移到 ElementArr → 消行/列时统计被清格元素。它的终点是「累加进静态目标 Collected[type]，凑齐即胜」——一次性的收集关。

本切片复用这条产元素链路的全部前半段，把它的终点（静态计数→胜利）替换成一条可循环的经济：

环节08 收集切片本切片（合成+订单+体力）
元素产出候选块携带（~22% 注入「仍需收集」类型）沿用，但注入类型改为当前订单所需（需求拉动）+ 保底
消除后Collected[type]++ 累加静态计数被清元素落入合成区，成为 Lv1 合成物
合成无新增：合成区相同元素两两合并升级（Lv1×2 → Lv2 …）
目标静态目标（◆×6、★×5），凑齐即胜新增：订单要求「指定元素 + 指定等级 + 数量」，交付得奖励、刷新下一单
资源约束无（无限落子）新增：落子耗体力、消除返还、订单奖励补充——技巧驱动「会消除 → 玩得久」
胜负凑齐胜 / 无可落子 GameOver完成 N 单胜（demo 终点）/ 棋盘塞满 或 体力耗尽 GameOver
「收集计数」语义裁决（boss 代决 §3 留给策划）：本切片替换而非并存——08 的静态 Collected[type] 累加胜利在本模式关闭，被清元素改为路由进合成区。08 已实现的「消除→统计被清元素」逻辑（CollectClearedElements）保留并扩展为「输出本次被清元素列表」供合成区摄入。两个模式各自独立门控，互不影响。

二、核心循环

七个环节首尾相接成环：奖励的体力回填到「落子」预算（正反馈回路），订单需求反向拉动候选块注入（只产订单要的元素）：

正反馈链：奖励的体力回填到「落子」预算；订单需求反向拉动注入与消除（只产/只消订单要的元素）。技巧（多消除）→ 体力净正 → 玩得久。

  • 两条产出随机性叠加：元素先要被注入候选块（概率），再要那一格被消除（落子技巧）。双重随机 = 高方差，须保底（见 §五·风险1）。
  • 两个失败条件：棋盘塞满无可落子（硬死亡，沿用 08 的 GameOver）；体力耗尽且无法支付落子（软死亡，「精力耗尽」面板）。
  • demo 终点：完成约定单数（默认 5 单）→ 通关面板。生产环境为无限订单流（仅靠失败条件结束），demo 设有限终点便于测试核对。

三、三系统设计

3.1 合成（Merge）

消除产出的每个元素以 Lv1 进入合成区；相同（类型 + 等级）两两合并升一级，直到封顶等级。

合成实现：自动配对库存（非空间拖拽）。合成区按 (类型, 等级) 记数量。新元素到达 → count[T][1]++；只要某 count[T][L] ≥ 2 即 count[T][L] -= 2; count[T][L+1]++，向上级联到无法再合并为止。这是 2048 式自动合成，不引入空间拖拽棋盘。
  • 为何不做浪漫餐厅式空间拖拽合成：拖拽合成板是另一套完整交互（格子布局 / 拖放 / 占位），与 demo「订单闭环优先」的范围冲突。自动配对完整满足「相同两两合并升级」规则，开发量小、可单测，把玩家心智留在方块层（落子/消除决策）。空间拖拽合成列为后续增强（见 §六）。
  • 封顶等级 MaxLevel = 3（Lv1→Lv2→Lv3）。到顶不再合并，堆积等待订单消耗。
  • 等级折算基础元素：Lv1=1，Lv2=2，Lv3=4。订单按此折算难度。
  • 合成区不设硬上限阻塞：自动配对使每类每级数量恒 ≤1（满 2 即合），库存天然紧凑，不会「塞满阻塞」，规避了一个数值风险。

3.2 订单（Order）

同时展示 ActiveOrders = 2 张订单。每单 = (元素类型, 要求等级, 数量)，例如「◆ Lv2 ×1」「★ Lv1 ×3」。

  • 交付（手动）：当合成区满足某单要求（库存有 ≥数量 的对应 (类型,等级)），该单「交付」按钮点亮；点击 → 扣除对应合成物 → 发奖 → 该订单槽刷新下一单。手动交付保留玩家「先交哪单」的取舍，且交付时机清晰可测。
  • 奖励：体力 +8（可溢出体力上限）+ 分数 = 等级 × 数量 × 50（示例）。奖励数值为可调常量。
  • 锯齿波难度刷新：保证「难单之后必出简单单」，每次会话都有够得着的目标。难度量 d(单) = 数量 × 2^(等级-1)（= 折算基础元素数）。刷新时下一单难度在「低 / 高」之间交替振荡（锯齿波）。
    demo 简化实现：用一张手编循环订单池预先编排好锯齿波节奏（如 易→易→中→易→难→易…），NextOrder() 顺序取下一项。完整的程序化锯齿波（依玩家进度动态算 d 并约束相邻单一高一低）规则写在本节，dev 先实现循环池版本即可满足闭环验收。
  • 体力瓶作为合成链产物（浪漫餐厅模型，本作改造）：部分订单奖励可发一个「体力瓶」合成物，体力瓶本身可在合成区合并（瓶×2 → 大瓶），「使用」时回大额体力。demo 范围内简化为奖励直接给体力；体力瓶作为可合成奖励物列为文档化的后续项，避免拖累闭环。

3.3 体力（Energy）

体力卡落子（本作的核心产出动作，对应浪漫餐厅卡「生成器」）。落子耗、消除返、订单补、自然恢复。

项取值（demo 可调常量）说明
起始体力 EnergyStart20开局可支撑约 20 次落子起步
软上限 EnergyCap30自然恢复 / 普通获取的封顶；奖励可溢出此上限

消除返还 ClearRefund= 本次消除行列数（1/行列）消 2 行返 2；技巧驱动「会消除→体力净正」

四、三个数值风险点的明确方案

boss 代决 §6 要求三个风险点在设计中给出明确方案，逐条如下。

风险 1 · 元素掉率方差 / 保底

本节注入机制已更新：下述「按 InjectChance 概率注入 + 保底计数器」的固定比例模型，已被 10 · 得分驱动元素生成替换为「消除得分 → 元素数量」的确定性映射；保底计数器随之退役。下文保留作历史设计记录。

问题：元素经「注入候选块（概率）→ 那格被消除（技巧）」双重随机，某订单所需类型可能长时间不出，订单卡死。

方案（三管齐下，前两条为主）：
  1. 需求拉动注入：候选块注入的类型池 = 当前激活订单所需的元素类型并集（不再是 08 的「所有仍需收集类型」）。把有限的产出集中到「正被需要」的类型上，直接压低「有用掉落」的方差。
  2. 保底计数器：记「距上次注入订单所需类型已过的落子数」pitySinceNeeded；超阈值 PityThreshold = 8 → 下一个候选块强制注入一个订单所需类型（绕过概率）。保证订单永不被随机饿死。
  3. 注入概率上调为可调常量：InjectChance 从 08 的 0.22 提到 0.30（订单要吞吐），作为配平旋钮，dev/test 可改数验证节奏。

风险 2 · 体力上限与单局落子数的匹配

问题：体力既要在早期不卡手，又要让玩家感到它是真实约束；上限/回速不能照抄浪漫餐厅（那是跨会话挂机节奏，本作是单局活跃节奏）。

方案（按本作局长重算，给出预算数学）：
  • 预算下界：无任何消除、无订单完成的最坏情况，起始 20 体力 = 20 次落子后软死亡——足够玩家撞出几次消除并完成首单。要求 EnergyStart ≥ 完成首单所需落子数的期望。
  • 可持续点：一个约 3 块的批次配 1 次单行消除 ≈ 净 -2 体力；每 ~6–8 次落子完成 1 单 → +8 体力 → 熟练玩家体力净正，单局实际由「棋盘塞满」而非体力终结——正中 boss「技巧驱动：会消除→玩得久」的定位。
  • 取舍定档：软上限取 30（demo 局长约数分钟）——高到早期不饿死、低到体力是被感知的资源。公式与各常量全部可调，dev/test 据此重配（核心不变量：EnergyStart ≥ 完成首单的落子数，否则首单前就饿死）。

风险 3 · 落错子的兜底（无广告）

问题：落子耗体力且可能把棋盘逼进死局；一次失误代价大，而项目红线禁广告复活。需要一个不依赖变现的解围阀。

方案 · 限次免费悔棋（推荐）：每局 UndoCharges = 3 次免费悔棋（无广告、无内购，纯次数限制，契合去变现）。
  • 悔棋范围：仅撤销最后一次落子（单步）。落子前对受影响状态打快照：棋盘 BinaryBoard、元素层 ElementArr、体力值、合成区库存、订单进度、保底计数器。悔棋 = 整体回滚到该快照 + 把方块退回待选槽 + 退回该次落子扣的体力。
  • 更轻的备选：仅当该次落子未触发消除（纯失误落子）时允许单步撤销，省去回滚消除/合成/订单的复杂度。若 dev 评估全量单步快照成本高，可先落地此备选版，全量快照列为增强。
  • 悔棋次数耗尽后回归正常死局判定（沿用 08 的 GameOver）。

六、与浪漫餐厅 / Gossip Harbor 的取舍

维度浪漫餐厅 / Gossip Harbor本切片取舍
合成交互空间拖拽合成板（格子布局 + 拖放）砍 → 自动配对库存。理由：拖拽合成是另一套完整交互，与「订单闭环优先」冲突；自动配对已满足「两两合并升级」规则。空间拖拽列为后续增强。
元素来源生成器周期产出改 → 候选块携带 + 消除掉落（本作的方块层就是产出动作），订单需求反向拉动注入
体力卡点卡「生成器产出」改 → 卡「落子」；且落子不保证消除（产出有方差），棋盘塞满是硬死亡——双失败条件是本作独有
体力数值上限 100、2 分钟 1 点（跨会话挂机节奏）重算 → 上限 30、单局活跃节奏；自然恢复保留但 demo 可简化，主补给来自订单奖励
订单难度冷却刷新 + 锯齿波取材 → 锯齿波保留（难单后必出简单单）；demo 用手编循环池实现，完整程序化规则文档化
体力瓶合成链上的可合并道具，使用回体力文档化后续 → demo 订单奖励先直接给体力；体力瓶作为可合成奖励物列为增强项
变现体力购买 / 广告 / 道具内购全砍（项目红线）→ 体力靠恢复+奖励，兜底靠限次免费悔棋，无任何付费/广告入口

八、Demo 范围

做什么（In Scope）

  • 体力系统：落子扣、消除返、订单补、自然恢复（可简化）、耗尽软兜底。
  • 合成区：消除元素入区 → 自动两两合并升级（封顶 Lv3）+ 显示。
  • 订单系统：双订单、手动交付（消耗合成物 + 发奖）、刷新、锯齿波（循环池实现）。
  • 掉率保底：需求拉动注入 + 保底计数器 + 可调注入概率。
  • 落错兜底：限次免费悔棋（单步快照回滚）。
  • demo 通关（完成 N 单 → 胜利面板）+ 双失败条件。
  • 独立窗口 + 主菜单入口 + 模式门控（Classic / 08 零影响）。

不做什么（Out of Scope）

砍掉原因
