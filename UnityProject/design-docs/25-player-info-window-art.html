五、GameContext 扩持有 PlayerInfo(延续统一上下文)

5.1 为什么纳入 GameContext

设计 23 §五已确立:GameContext 是「数据层已建、需运行期持有者」的无主系统的统一归宿,并明示「本轮先只持有 SettingsService;player-info / item / mail / rank 后续逐个挂入」。本轮兑现 player-info 那一项——把 PlayerInfo 的运行期持有 + 一次加载收进 GameContext,而非给 PlayerInfo 另套一个单例(避开设计 23 §5.2 方案 A 的「N 个系统 N 套样板」)。窗口只 GameContext.Instance.Player 取,与设置窗 GameContext.Instance.Settings 同源。

5.2 加载来源:并入既有 MergeMetaSave

玩家信息持久化不另造存储栈:设计 18 §3.8已把玩家字段平铺进既有 MergeMetaSave DTO,经 MergeMetaPersistence.Load 落盘 / 读取,PlayerInfo.ExportToMeta(dto) / ImportFromMeta(dto, rng, …) 是纯方法在 DTO 与模型间转换。GameContext.OnInit 里的加载分两路(dev 落地时按工程现状二选一,见下 callout):

protected override void OnInit()
