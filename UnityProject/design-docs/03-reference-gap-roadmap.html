原版功能差距 & 移植路线图

现状盘点 · 把「原版完整设计」「Web 参考工程」「Unity 当前版本」三方对齐，列清楚缺什么、数据现不现成、该先做哪个。

三个项目的关系：
  • 原版：com.block.juggle v7.7.6（Cocos 手游，已逆向）—— 设计的「完全体」。
  • Web 参考工程：template-vite-ts-zp（Phaser4 + TS）—— 按原版逆向复刻，含关卡数据 / 收集玩法 / 星级等完整结构，但特效与关卡推进逻辑自己也还没写完。
  • Unity 当前版本：本项目（TEngine）—— 从 Web 参考移植了「Classic 无尽」这一个切片，核心玩法 + 动态难度已完整可玩。
一句话：Unity = 原版的 Classic 切片；原版的关卡 / 收集 / 特效体系，Unity 这边都还没有。

三、重点缺口拆解

① Adventure 关卡模式（数据最现成，价值最大）

关卡数据已是成品 JSON（default360.json / default2000.json），结构清晰，Unity 只需做「读表 + 过关逻辑 + UI」：

字段含义
Map[64]8×8 初始棋盘：0=空，1-7=预置障碍方块（带色）。让每关有独特开局形状
levelTarget / Condition.RequiredScore过关目标分
Condition.Namescore_to_win（冲分）/ collect（收集）
RequiredCollections[]收集要求：Key=9999 表示分数，其余表示元素类型 + 数量
weightMin / weightMax本关 dynamicWeight 锁定区间 —— 逐关定制难度的钩子
设计杠杆： weightMin/Max 让关卡模式能复用 Classic 的橡皮筋系统做关卡级难度控制——同一套 DDA，关卡里把橡皮筋的活动范围一锁，就能精确编排「这关偏放水 / 那关偏做局」。不用另写难度系统。

② Combo 连击：补上从「计数」到「爽点」的最后一环

Unity 已有 Combo 计数变量但没用途（见 玩法总览）。原版设计里它驱动两件事：

  • 表现：连击弹字 text_combo / 满屏 text_perfect + 浮动加分
  • （可选）计分：连击倍率进得分公式 —— 目前 Unity 和 Web 参考都没把 combo 计入分数，是一个可选的数值增强点
这是性价比最高的小改：变量已在，只差表现层 + 一行倍率公式，就能显著提升消除手感。

③ 特效 / 音效：原版与参考都欠的账

消除动画、粒子、浮分、BGM——连 Web 参考自己都是 🔴 未做（它的 Phase 6 全部待办）。所以这块对 Unity 是「从零做」，没有现成逻辑可抄，只能参考原版手感。

四、移植优先级建议

按「价值 ÷ 成本」排序（成本受「数据/逻辑现成度」影响很大）：

优先级事项理由成本
P0Combo 连击表现 + 浮分变量已埋，立竿见影提手感，改动最小低
P0消除动画 + 音效当前无任何打击反馈，是体验硬伤中
P1Adventure 关卡（先做 score_to_win）360/2000 关数据现成，复用 DDA + weightMin/Max中
P1星级结算 + GameOver/通关界面关卡模式的闭环，ratios 现成中
P2收集玩法 collect需新增元素生成/收集计数系统，再加 114 关高
P3PVP 对战原版仅入口，无现成逻辑，工程量大很高
建议路线： 先用 P0 把 Classic 的「打击感」补齐（这是留存的地基），再上 P1 的关卡模式打开内容量。收集 / PVP 放后面，等核心体验立住。
