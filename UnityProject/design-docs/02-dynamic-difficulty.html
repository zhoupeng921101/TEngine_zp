动态难度拆解

现状分析 · 游戏最核心、最值钱的系统。它让发牌「会读心」:你顺的时候偷偷加码,你快死的时候悄悄放水,永远把你按在「就差一点」的心流区。

一句话原理: 系统维护一个隐藏变量 dynamicWeight(可理解为「最近有多惯着你」的累加器)。喂你简单块 → 这个值升高 → 触发「做局」档发难块;喂你难块 → 值降低 → 触发「放水」档发简单块。一根自动收紧又松开的橡皮筋。

一、调度总链路

每次手牌用完补 3 块时,DynamicWeightDiff.OfferTrio() 按优先级从上到下决策,命中即返回。整条决策流如下图:

各级的判定细节与数值:

  1. 调试强制档(ForceAlgorithm):HUD 调试用,非空时所有发牌都用指定算法。线上不触发。
  2. 清屏窗口(分数 < 15000):进入窗口后每回合强制喂「能清空棋盘」的方块(贪心钥匙算法),引导你清盘。清空后冷却 1~2 回合走普通调度,再开窗口 —— 制造「填满→清空」的张弛节奏。
  3. 优先级覆盖层(Override):特定时机插队接管。当前内置两条:
    • 开局首发 一局第一次补块走 FILL,确保你一上手就能消行,建立「这游戏会消除」的预期。
    • 空盘保护 棋盘刚清空时走 随机无死亡,避免清盘后立刻甩一个死亡难题。
  4. 未激活(未初始化 或 分数 < 1000):直接 随机无死亡,保证新手期绝不卡死。
  5. 正式动态调度:按 dynamicWeight + 当前分数选中一个 tier(难度档),再在档内按 8 个 odds 加权抽一个算法生成方块。
  6. 后处理:分数 < 10000 时套早期屏蔽(剔除超难大块);非清屏窗口期做三块去重(避免一组里出现重复图形)。

二、核心机制:dynamicWeight 橡皮筋

每次发完一组牌、玩家落子后,按所用算法给 dynamicWeight 加一个增量(AddWeight)。增量正负就是这套 DDA 的方向盘。

调权因子表(每种算法把权重推向哪边)

算法倾向首次/换向 增量同向连续 增量
ClearAll 清盘放水+60+30
Fill 填空消除放水+40+20
AllCombination 全组合放水+35+15
EasyDiff 简单难题偏易+30+12
RandomNoDie 随机无死中性+15+5
Add3 熵增偏难−25−10
Diff 困难难题做局−40−15
StraightDeathDiff 死亡难题做局−80−30
「同向连续」增量比首次小:连续放水/连续做局时力度衰减,防止权重一路冲到底,让橡皮筋更柔和。权重最终会被 clamp 到配置表覆盖的真实区间内。

三、8 种发牌算法逐一拆解

每种算法都返回 3 个 shapeId。难题类用「位棋盘启发式 + 蒙特卡洛采样」找最难的组合,放水类则找最好消的组合。

#算法目标实现思路(简)采样次数
0Fill 填空消除放水先找「快填满的行/列」,针对缺口定制线条钥匙块,凑出能消最多格的组合80
1RandomNoDie 随机无死保底纯随机抽,只要保证三块都放得下(不逼死)50
2Add3 熵增偏难挑让棋盘「最乱/碎片最多」的组合(最大化熵)60
3EasyDiff 简单难题偏难控制解法数量落在 5~30 这个「要想但想得出」的甜区80
4Diff 困难难题做局找最大空矩形塞大锚块,逼到解法数 ≤ 几种160
5StraightDeathDiff 死亡难题做局双锚块猛攻,专门找「只有唯一解或直接逼死」的组合320
6ClearAll 清盘 Plus放水棋盘格≥10 时,找一组能一次清空全盘的方块(大爽点)120
7AllCombination 全组合放水穷举落点找能消最多行列的组合(比 Fill 更激进)150
采样次数 = 算法的「努力程度」。死亡难题 320 次采样最舍得算力,因为「逼死你」比「放水」更难找到合适组合。这些数字目前硬编码在 BlockAlgorithms.cs,是一个可外置到配置表的调参入口。

真实权重表 block_tbweightcfg.bytes(Luban 生成),共 136 行 = 8 个分数段 × 17 个权重档。每行 13 个字段:tier id、8 种算法 odds、分数上下限、factor 区间上下限。

有意思的是:每个分数段的橡皮筋幅度几乎一致——最低权重档约 27~30% 做局,最高权重档约 92% 做局。

五、策划视角点评 & 可调参数

设计亮点: 用一个隐藏标量 + 一张二维表(分数 × 权重)就实现了平滑、自适应、玩家无感的动态难度,且把「难/易」拆成 8 种可独立调权的具体手法,调参空间极大。
可优化 / 可调点:
  • EasyDiff / StraightDeathDiff / Intuition 列几乎全 0——做了算法却没在表里启用,难度梯度其实只有「Fill ↔ Hard」两极。可考虑用上 EasyDiff 做更细腻的过渡档。
  • 翻脸太陡:权重过 10 这条线,做局占比从 18% 直接跳到 73%,体感可能是「突然变态」。可在 10~30 档加一个中间梯度。
  • 采样次数硬编码在代码里(死亡难题 320 次),建议外置到配置表,方便按机型性能/难度调。
  • 难度几乎只靠 dynamicWeight 调,8 个分数段区分度很低——高分玩家和中分玩家体验曲线几乎一样,可考虑让高分段整体更毒。
