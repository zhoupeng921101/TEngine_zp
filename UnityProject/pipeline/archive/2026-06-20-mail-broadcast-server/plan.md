### 启动播种细化(SV13 的本任务实现要点)

- **来源**:服务端进程启动时读同源导出的 `mail.xlsx`(server 端 Luban 产物或同结构服务端配置文件,具体落配置文件还是数据库集合 server-dev 定;32 §七 O8 默认)+ `mail_global`(`retain_days` 兜底)。
- **行为**:每条模板播种为一封**运营广播**邮件(目标 = 全服广播,有效期取模板 `expire_days` 或 `retain_days` 兜底,附件库 id 取模板 `reward_id`,收件时间 = 服务端当前时钟)。
- **幂等**:同模板 id 重复启动 = 不重复创建(以模板 id 为唯一键的条件写入,重复即 noop;或先查存在再插的二步若实现请上 MongoDB unique index 兜底)。这是「重启 / 多副本启动 / 配表热更」下的安全保证(SV5 同主题:并发原子写)。
- **不引入**:定时投递任务(brief 已说「本项目无 admin,可选『配置驱动+启动播种』模式」)、运营后台 admin RPC(O3 默认不做)、主动 push 协议(O11 / 后续刀)。

### 验收(本任务由 server-test 逐条核)

- 上表 SV1-SV14 中标「核心 · 落」的逐条核,SV10 复用 33 已 PASS 沿用结论(返修轮缩减策略已在 server-test memory):本任务**主验**SV1 / SV2 / SV5 / SV7 / SV9 / SV11 / SV12 / SV13;辅验 SV3 / SV4 / SV6 / SV8 / SV14。
- **真往返**:起服 + 启动播种把 `mail.xlsx` 模板播种为运营广播邮件 → 模拟两个不同账号会话拉列表 → 各自看到全服广播应收(过期已滤、领取态正确)→ 各自领取同一封 → 服务端两条独立记录(账号 A 已领、账号 B 已领)、两份奖励产物各按服务端抽奖(允许内容不同,因抽奖独立)→ 第二次领同一封返「已领过」、不重复发奖。
