# data-authority.md — 数据归属规约

> 上位原则:联网游戏的玩家数据,服务端是唯一事实源,客户端只持投影。新增任何持久数据先过本规约定归属,默认上服务端。

**适用**:所有 agent(主会话 / 流水线角色)新增或改动**玩家持久数据**(账号、进度、资源、成就、解锁、局内态等代表"玩家是谁 / 有什么 / 成就了什么"的数据)的归属与读写路径。

**不适用(留本地的白名单)**:仅以下两类留客户端本地(PlayerPrefs / 文件),不上服务端——
1. **设备偏好**:音量、语言、画质、操作设置等"跟设备走、换设备不必带"的偏好。
2. **可丢读缓存**:服务端数据的本地投影 / 离线兜底缓存(丢失可从服务端重建,非权威)。

> 白名单是防反噬的硬边界:无白名单则"全上服务端"会被教条执行,把音量设置也同步、烧流量砸离线体验。判据:该数据丢了能否从服务端重建?能 = 缓存(可本地);不能且代表玩家资产 / 进度 = 权威(必上服务端)。

## 核心原则

1. **归属·永远服务端** — 凡代表"玩家是谁 / 有什么 / 成就了什么 / 解锁了什么"的数据,服务端持有唯一事实源。客户端**不得**持有权威副本,只持投影:登录从服务端快照初始化、增量推送保鲜、变更经服务端裁定。**禁止**新增"本地即权威"的持久数据(白名单两类除外)。

2. **校验强度·按风险分级** — "数据在服务端"(归属)与"服务端校验每次变更的强度"(防篡改)是两个轴,不混。归属不可商量;校验强度按"被篡改的危害"分级,见决策表。

## 数据 → 机制决策表

新增一种服务端数据,按性质选机制,不自造新通道:

| 数据性质 | 机制 | 校验强度 | 准入判据 |
|---|---|---|---|
| 数值资源 / 进度(货币、计数、等级、标志位…) | **默认骨架**:玩家文档字段 + 类型化变更(PropertyChange)+ 流水账 | 限界信任(单次幅度上限 + 频率)校验后落账 | 绝大多数走这条 |
| 竞技 / 对外可见(排行榜、给他人看的分) | 校验提交 + 反作弊 | 服务端独立校验(异常检测 / 重算) | 一人作弊会坑到别人 |
| 大块、暂不值得逐字段建模(局内棋盘现场、杂项标志…) | 云存档 blob 同步(按玩家身份隔离) | opaque 存储,服务端不校验内容(弱读法:存服务端但客户端可改) | 纯可移植、低危、自己改只坑自己 |

> blob 一档是"存服务端 + 可移植",非"服务端对值有权威"。低危单机数据强行逐字段类型化是过度工程;真有高危标志混入,单独拎出来收编进 PropertyChange,不整层升级。

## 骨架(默认走这条)

- **写路径**:类型化变更入口(`C2G_PropertyChange`)——客户端上报"变更类型 + 增量 + 事由",服务端校验(限界信任)后落玩家文档 + 记流水。新增一种资源 = 加文档字段 + 加变更类型 + 加校验规则,不另起 RPC。
- **读路径**:登录快照(snapshot)初始化 + 增量推送(delta-push)保鲜。新数据并入快照,不另起查询 RPC。
- **客户端**:只持投影。乐观更新(不阻断手感)+ 服务端对账(以服务端值校正,哪怕与乐观值不同)。
- **身份锚**:玩家身份(playerId)服务端登录签发、唯一不可伪造——所有按玩家寻址的服务端数据(榜、存档)以此为键。

## 验收闸

- 新增持久数据**默认上服务端**;要立"本地即权威"的存储,交付时**显式论证**它属白名单两类(设备偏好 / 可丢缓存)之一,否则 review 拒。
- 验收方(boss / test 在 code review)核对:有无新增本地权威存储而未论证;资源 / 进度类数据是否走骨架而非自造通道;客户端是否只持投影、变更是否经服务端裁定。

> 本规约是上位默认。流水线角色卡里"服务端权威存储 / 服务端权威时钟 / 客户端短路本地排序"是其具体执行,不重复、不冲突。
