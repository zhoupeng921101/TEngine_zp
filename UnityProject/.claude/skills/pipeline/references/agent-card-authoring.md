# 角色卡写作标尺：把判断编译成可执行条款

> 用途：写或修订任一 pipeline 角色卡（plan/dev/test/ui）时读。判断「这条卡片条款合格吗」的标尺。
> 与准入的分工：`.claude/rules/conventions.md`「规则准入」管一条条款**能不能进卡片**（查重/分层/触发/反噬/反向冲突）；本文管它**进去后怎么写得可执行**。两者不重合，不复述准入 5 问。

## 中心命题：质量由可执行程序决定，不由身份标签决定

给 agent 写「你是资深策划」这类**身份标签**，只给了它一个名字，没给判断动作本身。模型只能照名字模仿语气（显得更自信），产出不会真的变好。

「资深」的实体，是一套被经验校准成反射的**判断动作**：先想机制会怎么崩、先问需求是不是真需求、张口给得出数值量级。把这些动作写成条款，普通执行体照着做，产出就逼近资深。**卡片要装的是这套动作本身，不是它的名字。**

## 合格条款 = 触发条件 + 具体动作 + 可核对产出物

一条判断类条款，三要素缺任意一个就塌回成形容词——模型可以一边点头一边什么都没做。

| 要素 | 它定死什么 | 缺了会怎样 |
|------|-----------|-----------|
| 触发条件 | 什么时点必须执行 | 无触发点 → 永不执行的空条款 |
| 具体动作 | 执行体要做的那个动作 | 只剩愿望，不可执行 |
| 可核对产出物 | 执行后留下什么、验收方据什么核 | 无法验收 = 等于没做 |

**反例（形容词冒充条款）**：「设计要严谨」「考虑周全」「注意边界情况」——无触发、无动作、无产出物，三者皆缺。

**正例**：见 pipeline-plan 卡的「设计稿章节骨架」与「设计自检」两节——这两节的判断类条款是按本标尺写的 worked example，把「想失败模式」「问真需求」「收范围」等资深反射各自写成了带产出物的强制工序（具体条款以该卡现状为准）。

写条款时拿三要素逐一对：这条说清了「何时触发」吗？给出了「做什么」吗？留下了「验收方能核对的痕迹」吗？

## 可程序化光谱：决定一条判断写成「强制产出物」还是「交人判的脚手架」

不是所有判断都能硬化成强制条款。一条判断越有客观锚点，越能写成「必须产出 X」；越靠「在模糊处选对方向」，越只能写成「把取舍摆上桌、交人判」。

| 判断类型 | 客观锚点 | 该写成 |
|---------|---------|--------|
| 数值/公式/边界 | 强（有标准答案） | **强制产出物**：公式 + 常量 + 边界逐档代入表 |
| 失败模式（它会怎么崩） | 中（枚举得出来） | **强制产出物**：每个机制一行崩法 + 对策 |
| 范围收敛（哪些可砍） | 中（可砍判据明确） | **强制产出物**：每功能点标核心/增强/可砍 |
| 问题重构（是不是真需求） | 弱（问得出、答得好靠判断） | **半强制**：强制问降层，答得好不强求 |
| 方向取舍（几个方案选哪个） | 无（纯 taste） | **只搭脚手架**：取舍显式列出 + 给理由，交验收方判，不替它判 |

规律：**有标准答案的判断硬化成产出物；靠 taste 的判断只搭脚手架。** 把纯 taste 写成「必须选对」是假条款——执行体选错了也满足「做了选择」，条款拦不住。

## 优先瞄准「模型会做但默认偷懒」的动作

对 LLM 执行体，条款的收益不均匀，**最大的一档是把「模型本来会、却默认跳过」的动作拽到必做档**：

- 模型的知识广度接近「读完了所有设计文档」——「先想失败模式」「先问真需求」它会做，只是默认省略。条款把这步从可选变必做，收益最大。
- 模型根本不具备的能力（如某领域的实测数值直觉），条款给不了——**别用条款假装补上**，那只会逼出编造。这类缺口要么提供数据，要么标为「交人提供」。

写条款先分类待写的动作：**会做但偷懒 → 写强制条款（高收益）；压根不会 → 提供数据或交人，不假装。**

## taste 残量：诚实标注，交验收方补

有一档判断，标签补不了、条款也补不了：一堆失败模式里**哪个才致命**、几个方案里**哪个方向对**、何时该**破既有条款**。这些是「生成、取舍 checklist 的能力」，不是 checklist 本身。

写卡片时对这一档要诚实：**不假装条款能判，显式把判断点暴露出来交验收方**（如 pipeline-plan 卡用「待拍板清单」集中列出取舍交 boss/用户）。把 taste 伪装成可判定规则，比留空更糟——它让验收方以为「已经判过了」。

## 写卡片 recipe

1. **找反射动作**：列出「这个角色的资深执行体会做、新手会漏」的具体动作。
2. **逐条写三要素**：每个动作配上 触发条件 + 具体动作 + 可核对产出物。
3. **按光谱定形态**：有锚点 → 强制产出物；靠 taste → 只搭脚手架交人判。
4. **标注残量**：压根写不成条款的 taste，显式交验收方，不假装。

## 审卡片 checklist（把本标尺施加到任一角色卡）

逐条过该卡的判断类条款：

- [ ] 每条判断类条款，触发条件 / 具体动作 / 可核对产出物三者齐全？
- [ ] 有没有形容词冒充条款（「要严谨」「考虑周全」，无产出物）？
- [ ] 有没有把 taste（纯方向取舍）写成「必须选对」的假条款，而非交人判的脚手架？
- [ ] 有没有用条款假装补「模型压根不具备的能力」，从而逼出编造？
- [ ] taste 残量是否显式标注交验收方，而非留空或伪装成规则？

> 本节是无时点的审计程序：对任一角色卡都适用，不记录某张卡「当前是否已对齐」——那是会过时的状态。
