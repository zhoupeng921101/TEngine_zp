# 规则审计

触发:用户手动 `/audit`(或要求"审计规则/查规则栈")。先查增量:规则栈自上次审计(基线记 `.claude/rules/audit-log.md`)无改动 → 记「无变化,跳过」即止,不做全量;有改动才查(1-3 必查,4-6 条件查):
1. **重复** — 同一行为多处有源;疑似与模型/框架内置重复的条款,跑行为探针复核(基线已达标 → 删除候选)。
2. **死规则** — 连续多轮审计都举不出触发实例的条款 → 删除候选(单次窗口不判死,看累计)。
3. **矛盾** — 条款互相冲突,或与近期实际行为冲突。
4. **信道匹配**(仅当注入集有增减时)— 本次有文件新进/移出自动注入路径(`.claude/rules/` 递归)→ 核它该常驻注入(规范层、每轮相关)还是该移出按需读(角色专属/日志/数据层)。无增减则跳过。
5. **净增趋势**(顺手记一行,观察非硬上限)— 注入态 `.claude/rules/` 总行数 vs 上轮;连续多轮净增且无对应删除 → 升「总量复查」候选。
6. **孤儿旁注**(仅当本次有规范被覆盖/删除时)— 核被改/删规范的 `>` 旁注是否随之清理,并抽查若干现存旁注其父规范是否还在。

执行要点:

1. **增量短路**:读 `.claude/rules/audit-log.md` 的上次审计基线(git rev/日期),规则栈自基线无改动 → 在 audit-log 记「无变化,跳过」即止
2. **规则栈范围**:项目根 `CLAUDE.md`、`.claude/rules/`、`.claude/skills/*/SKILL.md`、`.claude/skills/tengine-dev/conventions-dev.md`(dev 开发规约,已移出注入路径)、`.claude/agents/*.md`、`pipeline/memory/*.md` 文件头准入规则
3. 有改动 → 按上方查项查(1-3 必查,4-6 按触发条件)
4. 结论叙述写入活账本 `.claude/rules-archive/audit-log.md`(注入路径外,一次审计一段);并更新注入态 `.claude/rules/audit-log.md` 的最近审计基线指针(一行)
5. **删除候选先报用户拍板,不静默删**
