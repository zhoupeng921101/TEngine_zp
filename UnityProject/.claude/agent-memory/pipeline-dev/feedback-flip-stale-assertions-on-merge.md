两窗合一(融合)时,既有窗口的换皮零回归测试断言会与融合意图冲突:设计 26/27 换皮期写的「MergeOrderWindow 不得引用 Sheet_tarot_mode」「GameOverWindow 重试→GameWindow」类断言,在融合后恰恰要反过来(融合主体须承载皮、结束窗重试回融合窗口)。这类断言须随融合同步更新(测试是验收方资产,改动者同步改、不留给 test 报假阳越界);更新后保留核心零回归断言(坐标常量不动、经济逻辑链关键行仍在),只翻转被融合改变前提的那几条。

塔罗皮移植到融合主体=纯静态视觉壳照搬 `SetSubSprite` 调用(背景/外框贴 chessboard/chess),坐标全用 `BlockLayout` 既有值,与零回归红线天然兼容;经济 HUD 在塔罗精灵表无对应子图时维持纯色+glyph(同既有窗口占位 stub 镜像),配套子图是另一轮美术,不在融合范围。

**Why:** 旧断言基于「分离窗口」的设计前提,融合后这些前提已不成立,断言报错的是新设计意图而非真 bug;留给 test 处理会被定性为「dev 越界改测试」或「test 不负责改」陷死锁(2026-06,gameplay-fusion)。

**How to apply:** 任务有融合/合并/反转设计时:① 先列「现存断言基于的设计前提」;② 找出被新设计反转的前提条目;③ 同步翻转对应断言(写在同一次提交);④ 保留与设计正交的核心红线断言(坐标/经济逻辑链);⑤ 交接里显式注明「翻转了 X 条断言因 Y 设计反转」。
