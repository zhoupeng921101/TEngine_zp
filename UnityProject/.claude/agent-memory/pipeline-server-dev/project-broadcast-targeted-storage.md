「广播 + 定向」两路插入、一套领取的存储模型:

- **广播来源**:全服模板,缓存遍历
- **定向来源**:按账号集合 + Account 索引查
- 合并下发;对外标识用前缀区分来源(广播 `"t{模板id}"` / 定向 `"d{guid}"`)
- 按账号防重记录的 `_id="{account}|{标识}"` 两路键空间不重叠
- 同一套原子防重 / 抽奖兼容两路

**Why:** 「运营广播全服模板邮件」+「系统定向给某账号发奖」两类入口共存时,若用同一份 `inbox` 集合塞两路记录,需区分来源(运营改广播模板时定向记录不受影响);若分两个集合,客户端查 mailbox 要并两路再排序,繁琐。前缀方案让两路在同集合并存而防重键不冲突。

**How to apply:** 设计新「面向账号下发」类系统(典型:邮件/奖励/通知)需「广播+定向」两种入口时,沿邮件先例:① 模板/广播表;② 定向记录表;③ inbox 防重表(`_id` 复合);④ 对外 id 加前缀区分。客户端不感知前缀,只把 `mail_id` 原样回传服务端核对。
